# Freedom14 生物跟随修复说明

## 修复范围

- 没有 E 键互动、没有对话、没有人类语音的角色也可被工具直接登记为随从。是否可对话不是跟随条件；不改共享种族的对话标记
- 保留既有 512 个独立任务别名、距离档位、龙盘旋模板、战斗规则和等待/冻结规则
- 优先执行原别名跟随包；原包反复抢回时，每两秒最多尝试一次完整的已有跟随程序，作为该引用的临时包。明确传入 `createdPackage=false`，不创建残缺程序树，不修改共享包或 NPC 模板
- 读回当前实际包，不能仅凭别名绑定或缓存指针称为成功。模型/AI 就绪与跟随包确认分别计数；确认超时仍保留军团登记并继续维护
- 对登记后的延迟脚本阵营变更重新隔离，同时保留首次观察的原等级供解除控制恢复
- 个体与全军等待/继续共用同一个控制路径；全局冻结期间点个体“继续”也不会启用 AI
- 生成期间下达等待、冻结或解除控制后，后台出生检查不会再擅自启用 AI 或重新招募；解除/移除同时取消后续出生属性和落点改写
- 已进入战斗的出生实例不再被模型就绪检查重新吸附导航网格
- 解除控制时移除本工具的临时跟随包，并重新评估原 AI；全局冻结仍然优先

## 能力与导航限制

- 依据实际种族的 Walks / Swims / Flies / Immobile 标记选择纠偏方式，不把所有非龙生物当作地面角色
- 飞行、游泳中、纯水生和固定型角色不会被强制吸附到地面导航网格
- 纯水生角色不瞬移到陆地玩家脚下；仅能行走的角色不被纠偏到游泳玩家的深水落点；地面角色不在玩家仍滞空时纠偏
- 纠偏使用已加载的玩家落点，不再对未验证的队列圆环坐标直接 SetPosition，避免穿墙定位；重复纠偏有三秒冷却
- 固定型/缺失移动能力的种族只能用限频位置纠偏保留队伍位置。这不能制造缺失的模型、动画、碰撞或导航能力，也不声称它们已实现正常行走
- 有效战斗中的随从不会因跨区域而被跟随维护传送或覆盖战斗包

## 可确认的旧代码缺口

1. 出生检查在模型与 AI 过程存在时即结束，未读回跟随包
2. 阵营隔离仅运行一次，延迟初始化/加载脚本添加的阵营可绕过它
3. 原生别名不断失去优先级时只重复 EvaluatePackage，没有针对单个引用的完整已编写程序回退
4. 所有非龙角色都吸附地面网格，未区分水生/飞行/固定型
5. 等待期间出生检查可启用 AI；解除控制后未完成的出生任务可再次招募该引用

这些是源码中的控制流程问题；没有针对用户完整游戏加载顺序及具体 DemonicCreatures 实例运行游戏，不能将某一个问题断言为每种失败生物的唯一原因

## 运行诊断

首次招募日志记录引用 ID、实际种族和移动能力。持续拒绝时按每个引用最多十秒一次记录：

- 引用 ID、NPC 基础记录 ID、种族 ID
- 当前包 ID、期望包 ID、别名槽位
- AI、模型、AI 过程是否存在
- 行走、游泳、飞行、固定、龙的分类

无需 E 键互动即可从工具选择目标并采集这些信息。批次计数是该批检查时的快照，后续恢复以成员当前状态为准

## 兼容性与验证边界

- FreedomControlRuntime.esp 与 INPUT13 原件字节一致，无新增或更改记录，也不要求重新开始存档
- 新重试/冷却/计数字段只保存在内存；既有阵营及原控制状态的保存格式不变
- 可移植策略测试和直接编译生产 Legion/Follower/Spawner/WorldFreedom 源文件的测试替身覆盖：包拒绝及回退、静默生物、迟到阵营、恢复原等级、等待/冻结/战斗、不同导航能力、出生读回和解除后不重招募
- 这些测试不验证真实 CommonLib ABI、Skyrim 原生内部行为、动画资源或游戏稳定性。Windows x64 MSVC 构建和 Skyrim 1.6.1170 实机回归仍须执行

建议实机依次验证：普通人形、可跟随及不可跟随各一只 DemonicCreatures、跨门/跨区域、等待/继续、冻结/解除、战斗/和平、招募后存读档、解除控制、纯水生及飞行生物。确认同基础记录的未招募实例没有变化
